# Flow UX 设计备注

状态：设计备注 / 待拆分实现。
来源：2026-05-28 手工测试与用户视角复盘。

## 目标

让用户更容易判断一个 Flow 是否能运行、为什么不能运行，以及按钮、数据源、变量等配置是否已经正确绑定。

## 优先级最高的问题

| 优先级 | 问题 | 用户感受 | 建议方向 |
|---|---|---|---|
| P1 | Data Source 运行时需要选择 CSV，但入口不够前置 | 用户点运行后才被打断，不清楚 Data Source Flow 本来就需要每次运行选择 CSV/TSV | 在 Flow 卡片、编辑器和运行前检查中直接显示同一类“运行时需要选择 CSV/TSV 文件”提示，提供一致的“选择并运行”入口 |
| P1 | Flow 可以保存明显跑不通的默认示例配置 | 用户保存后运行失败，才发现 `.btn-primary`、`.status`、`https://example.com` 仍是示例值 | 保存前做轻量校验，提示空字段、示例 selector、示例 URL；默认允许保存但标出风险，`Save & Run` 需二次确认后才继续 |
| P1 | Elements 里绑定 Flow 后显示 raw id | 用户看到 `flow-test-03-variable-popup` 不知道对应哪个 Flow | Elements 卡片摘要、详情行/抽屉和 Flow 下拉已选项都优先显示 Flow 名称，raw id 放到 tooltip 或调试信息里 |

## 配置体验问题

| 优先级 | 问题 | 用户感受 | 建议方向 |
|---|---|---|---|
| P2 | 变量语法偏工程化 | 用户容易把 `{{var.name}}` 写成 `{{vars.name}}` | 保留现有提示，并继续增加变量插入菜单、自动补全、错误 token 高亮 |
| P2 | Data Source 列名可点击但不够明显 | 用户可能不知道点击列名会自动生成 Input step | 将列名做成更明确的按钮样式，增加“点击插入列变量”的微文案 |
| P2 | If/Else、Loop、Data Source 嵌套后层级难读 | Flow 复杂后不容易看清当前在配置哪一层 | 增强缩进、折叠、分支标题和当前运行 step 高亮 |

## 列表与运行体验问题

| 优先级 | 问题 | 用户感受 | 建议方向 |
|---|---|---|---|
| P2 | Flow 列表运行和删除按钮距离太近 | 小按钮并排，误点删除风险高 | 拉开距离；删除使用二级入口或更强确认；运行按钮保持主操作地位 |
| P2 | 运行状态和日志偏开发者视角 | 普通用户更想知道“正在做什么、哪里失败、怎么修” | 在日志外增加用户友好的摘要，例如“正在填写 Customer ID”“找不到 selector .status” |
| P3 | 配置步和运行步口径容易混淆 | Data Source 按行展开时步数不同，用户会困惑 | 已将列表显示为“配置步”、运行状态显示为“运行步”；后续可增加 tooltip 解释 |

## 推荐实现顺序

1. Data Source 运行时选文件提示：卡片、编辑器和运行前检查统一提示。
2. Flow 保存前轻量校验：示例 selector、示例 URL、空必填字段。
3. Elements 绑定 Flow 展示名称而不是 raw id。
4. 变量插入与错误 token 高亮。
5. 嵌套步骤可读性与运行摘要优化。

## 验收标准草案

- Data Source Flow 在 Flow 卡片、编辑器和运行前检查中显示同一类“运行时需要选择 CSV/TSV 文件”提示，并提供同一入口选择文件后运行。
- 使用默认示例 selector/URL 的 Flow 保存时出现警告，警告能指出具体 step；直接保存可以继续但要保留风险标记，`Save & Run` 需要用户二次确认后才运行。
- Elements 卡片摘要、详情行/抽屉、Flow 下拉已选项中的绑定信息显示 Flow 名称；删除或找不到目标 Flow 时显示清晰降级文案。
- 用户输入 `{{vars.name}}` 这类不支持 token 时，编辑器能提示它不会被替换。
